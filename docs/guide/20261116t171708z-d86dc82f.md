### [#345] GUIDE-1. Graphics defaults changes the list look without marking unsaved

**Disposition:** repair, P3. **Verification:** reproduced missing dirty event; downstream saved/guarded-load consequence traced in source.
**Principle/contract:** `vision.player-information`; CK-311 r2 rule 5 explicitly includes list-look changes through the settings tab. CK-308 resets that choice; CK-330 displays the core's latest unsaved flag.

**Evidence:** at this pin, [settings_window.lua](../../scripts/ui/lib/settings_window.lua) lines 267–285 calls `settings.reset("graphics")` and `list_look.refresh()`. [list_look.lua](../../scripts/ui/lib/list_look.lua) lines 22–37 marks after an effective `set`, but `refresh` only publishes. The real UI-rig probe chooses rows, then presses defaults: the shared choice returns to cards, but the mark count remains 1 instead of becoming 2. Evidence: `.pipeline/coordination/guide/20261116t171708z-d86dc82f/defaults-unsaved.log` and `probes.patch`.

**Consequence:** after a successful save while paused, defaults can change rows to cards while the game still reports saved. The next guarded load can therefore proceed without the confirmation CK-311 requires for this choice. The probe directly proves the missing message, not a complete native save/load session; ordered-core tests and source establish the downstream consequence. No loss of world simulation data is asserted.

**Deduplication:** authenticated manager answer `96ttbyrhm4ycnhzhhui4xmapbw` confirms no issue, ruling or deferral. The owner's passed `gfx-defaults2` check covered reset/look propagation, not the dirty flag; it does not waive CK-311.

**Smallest action:** keep the shared list-look change path responsible for the dirty mark whenever an effective user reset changes the choice. Preserve the no-game guard, no-op behavior, panel notification and existing resize behavior. Do not mark unrelated graphics settings unsaved.

### [#346] GUIDE-2. The settings input list rounds each fine wheel delta

**Disposition:** repair, P3. **Verification:** reproduced in both directions through actual UI-rig pointer dispatch.
**Principle/contract:** `vision.ui-heavy` and `vision.responsiveness`; CK-323 r2's wheel routing over the input list, with CK-266's repaired cards demonstrating the raw-position/visual-snap distinction.

**Evidence:** [settings_window.lua](../../scripts/ui/lib/settings_window.lua) lines 204–213 stores `ui.snap(pos)` as `page.scroll`, then uses that snapped value for the next point-unit event. With `ui.P = 2`, starting at scroll 20, two +1-point events leave 20 (expected 18), while two −1-point events produce 24 (expected 22). Both probes fail at their executed final assertions. Evidence: `.pipeline/coordination/guide/20261116t171708z-d86dc82f/precise-scroll.log` and `probes.patch`.

**Consequence:** a high-resolution wheel or trackpad can fail to move upward at all for repeated one-point events and move twice as far downward. This is a new settings implementation of the already-repaired card-rounding pattern, not a regression in CK-266's cards.

**Coverage weakness in the same concern:** `settings_input_wheel_case`, [menu_tests.rs](../../apps/codekarl/src/ui_link/menu_tests.rs) lines 814–887, queues the final `s.page.scroll > 0` assertion in an opened callback step, then calls `frame()` without the final `rig.opened()`. The rig consumes these steps only on `opened`; that final scrolling assertion is never evaluated. The guide probes explicitly execute it.

**Smallest action:** retain a clamped unsnapped input position; snap the drawing/hit/bar geometry at its boundary. Cover repeated small deltas in both directions, accumulated fractional movement, end clamps, content shrink and retained scroll after a binding change. Correct the existing wheel test's final-step execution. Keep this independent of GUIDE-1.

**Deduplication:** manager answer `96ttbyrhm4ycnhzhhui4xmapbw` confirms no issue, ruling or deferral. CK-266's review note about rebuilding hit keys on small steps is a different symptom.

**Accepted repair:** CK-346, batch `1794852805254564000`. Raw position accumulates while geometry snaps. The 29 focused input tests and both original independent scroll probes pass. See [the final follow-up](20261116t182538z-c90afad9.md).
