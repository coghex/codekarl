## Findings

### [#83] GUIDE-1. Repair the Vulkan test support's undersized native output structure

**Disposition:** repair, recommended bug/P2, first in this follow-up walk.

**Verification:** verified at the pin, including a compiled layout/write probe.

**Principle:** `vision.small-libraries`; the FFI wrapper's explicit safety claim and the acceptance tests' requirement to provide valid evidence.

**Evidence:** `crates/gpu-vulkan/tests/support/mod.rs:6` still defines `RawInfo` ending with `filtered_keys`. Its `info()` at line 36 allocates that type and passes its pointer to `ck_glfw_test_info`. CK-82 added `activation_policy` and `is_active` to `crates/window-glfw/tests/native/testing.h:25`, and `testing.m:48` writes the entire enlarged structure, including an initial `memset`. `crates/gpu-vulkan/build.rs:12` compiles that same native source. `crates/gpu-vulkan/tests/window.rs:216` calls the wrapper while opening a test window.

The probe compiled the exact Rust structure and the actual accepted native implementation on this Mac:

```text
Rust RawInfo size=336 align=8
C CKGlfwTestInfo size=344 align=8 new_fields_offset=336
Bytes written beyond old Rust allocation: ff ff ff ff 00 00 00 00
```

The write probe deliberately allocated the full C structure, initialized it to `0xa5`, and observed the tail. It therefore demonstrates the eight extra bytes written without itself overflowing an allocation. The production test wrapper supplies only 336 bytes. Probe sources and commands are preserved as `abi-size.rs`, `abi-write.c`, and `abi-probe.json` under `.pipeline/coordination/guide/20261021t122138z-9c447a99/`.

**Consequence:** the Vulkan window test wrapper has an out-of-bounds native write and undefined behavior; adjacent stack state can be corrupted. This is test-only code, not a demonstrated application memory error. All 68 Vulkan window cases reported success in this run despite the mismatch, illustrating why those results cannot establish memory safety. Neither CK-82's effective scope nor an existing open issue covers this consumer repair.

**Action:** reconcile every consumer with the C ABI and add a direct layout regression guard. Also make the Vulkan test-support build track the included header, currently absent from its explicit `rerun-if-changed` inputs. Preserve the test-only linkage and keyboard filter. Do not redesign the runtime or change activation policy.

**Approved draft — filed as CK-83:**

## Brief assessments and limits

- **Activation helpers:** the general GLFW and Vulkan rigs still activate explicitly. They do not independently prove product activation. CK-82 now has a separate case that creates a window without the helper, observes regular policy/active/key state, and delivers marked Escape through dispatch. No further masked product-state defect was established in the inspected Cocoa, Metal or app paths. Scale overrides, scripted closes and forced GPU outcomes are explicit stimuli, not evidence of spontaneous product behavior.
- **Lexical guards:** retain them as tripwires, not semantic proofs. `MAIN_THREAD` substring matching rejects a harmless status name (the recorded CK-82 incident); the hook-name scan also includes comments and literals. Sharpen those when touching their checks, with positive and negative fixtures. The CK-80 unsafe-word counter already strips comments/literals and tests that behavior; its count still cannot prove an unsafe operation is sound. GUIDE-1 is the practical counterexample to relying on text checks alone. No separate speculative parser project is proposed.
- **CK-79 design choices:** current-configuration suboptimal results avoid pointless rebuilds; changed surface configuration still triggers one. Backoff is 50 ms to 1 s, with triggers able to retry sooner and no arbitrary failure count. Runtime retirement releases only proven idle resources; teardown first seeks proof for everything and retains all on an unproven end. Unproven readback retains instance/loader. These mechanisms fit design §§7–8 and the effective r5 clauses; no additional owner decision was identified.
- **Loader and refusal:** traced shared ownership across GLFW, instance, presenter and readback. Proven teardown releases presenter resources, surface, instance, window, GLFW/NULL reset, then loader ownership. Refusal or unproven cleanup retains the dependent objects and exit 3/latch semantics. Application fake-stack tests exercise both already-destroyed and retained surfaces, and a panic during the late drain. No new production lifetime defect was established.
- **Earlier loose ends:** the TLS-test settle sleeps remain a possible determinism improvement, not a reproduced defect; the historic `test_08p` flake was not reproduced. The master policy's general full-CI wording describes batch acceptance; the accepted AGENTS/category rule governs focused worker checks. None warrants a new repair on this evidence.
