## Findings

### [#154] GUIDE-1. Release the upload-store lock before the stop-path room notification

**Disposition:** owner-approved repair, filed as CK-154. **Priority:** P2.
**Verification:** source-verified reachable lock cycle; no runtime reproduction or probe.
**Principle:** `vision.runtime-first`, `vision.small-libraries`; CK-112’s after-unlock wake contract.

**Evidence at the pin:**

- `crates/gpu-metal/src/textures.rs:1119` promises that owner notifications run after the store lock is released. CK-112’s effective spec, “The two handles”, makes the same promise.
- `textures.rs:2030–2063`: the worker waits for staging with `Shared.state`. If stop becomes true, it resolves waiting items and updates occupancy, then calls the room notification at line 2062 without dropping `state`.
- `textures.rs:1822` invokes the configured hook synchronously. `UploadPort::room()` at `textures.rs:1243–1244` locks the same state.
- A room hook that performs that ordinary capacity query therefore deadlocks on this stop path. The worker cannot finish; the owner can block reacquiring the mutex during proof, beyond its intended deadline.
- Other notification paths release the state guard first (`textures.rs:2358`, `2374`, `2431`). The stop/staging regression at `crates/gpu-metal/tests/textures.rs:5531–5587` uses default empty hooks and misses this interaction.

**Impact and boundary:** this affects a direct store client using the public room notification and query. The application’s current `texture_marker` hook only sets a separate slot flag (`crates/gpu-metal/src/presenter.rs:500`); no observed application hang is claimed. This is distinct from the old-ticket mapping defect already assigned to CK-150.

**Deduplication and authority:** authenticated manager answer `mn9q3zqd6dxxj8p9msrjs5f74a` (2026-10-30), fully read and claimed, reports no existing issue or owner exception. That answer confirms context, not repair authorization. The relevant source was rechecked against the accepted docs copy before this draft; the finding remains present.

**Recommendation:** complete the stop transition under the lock, drop the guard, then notify room, following the existing other paths. Keep the repair local, preserve accounting and proof-before-release, and use the normal manager-led spec/submission gates.
