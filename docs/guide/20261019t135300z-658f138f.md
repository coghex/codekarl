## What moved

- **CK-53** (batch 1792398352191119000) supplies the thread-confined Lua owner, caller-observed states, immutable configuration proxy,
  host logging, errors and captured per-owner stdout flush. CK-57 subsequently separates requests from waits; CK-55 replaces the
  initial cooperative-only cancellation with the instruction hook. These amendments were considered together, rather than treating
  the superseded CK-53 clauses as current behavior.
- **CK-57** (1792401282025758000) permits multiple startup/shutdown requests to be in flight. A successful stop requires observation
  of actual thread completion; a reply alone is insufficient. The rendezvous tests exercise overlap, not just fast sequential runs.
- **CK-55 and CK-56** (1792405532559756000) integrate Lua cancellation and generic supervision. The supervisor tracks owners from spawn,
  sends stop requests before waits and potentially delayed logging, cancels every owner on start failure, and retains deadline misses
  even when a cancelled thread later finishes. Protected-call wrappers preserve ordinary results while preventing cancelled scripts
  from repeatedly swallowing the hook error. The runtime has no Lua dependency.
- **CK-58** (1792408324792710000) wires the pieces through an app-local adapter. Configuration-relative entry paths, strict timeout/name
  parsing, copied configuration and sorted dispatch match the effective spec. Bare invocation keeps the M1 no-VM path. Missed deadlines
  or unfinished owners force the incomplete exit even if the logger finishes; ordinary script failures remain failures, not clean exits.
- **CK-54** (1792400042886539000) makes status, inventory and recheck use the same changed-definition rule. Changed previously covered
  closed issues return to review, while state-only changes retain coverage. The fresh 89-test suite covers this repair.
- **Supporting docs:** three runtime-design amendments and the final README/design publication describe the accepted choices and
  limits. Three prior guide publications preserve the earlier report, finding filing and delivery; reading that bookkeeping does not
  freshly re-review the earlier M1 implementation.

The supported boundaries remain material:

- Lua instruction cancellation cannot interrupt blocked native calls, Lua finalizers or the documented same-frame close-handler case.
  The executable bounds its wait and reports incomplete exit; it does not claim those threads were cleanly stopped.
- C stdout is shared. Under a blocked print, the sibling shutdown callback can run while its own final flush also blocks. The amended
  design and tests distinguish callback progress from completed teardown. Mixed native-print/log output can interleave.
- No sandbox, inter-VM message system, game scheduler, window/rendering integration, mod loader or simulation-performance claim is
  delivered by these skeletons. Those are future design work, not missing M2 acceptance criteria.
